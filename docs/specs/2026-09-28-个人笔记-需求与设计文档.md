## Context

当前项目目录中只有需求提示词、参考截图与图片素材，**尚无任何代码**，属于从零起步的新项目。

要解决的问题是：为一款个人向在线笔记应用做需求与界面设计定稿。该应用需要覆盖账号体系、笔记的写作与发布、分享、评论、收藏、Markdown 渲染，以及与写作体验强相关的 AI 润色能力。

本轮的产出是**需求与设计文档**，作为后续技术方案与实现阶段的唯一依据。`项目截图/` 中的五张图已经是目标形态的参考实现，本文档以它们为准做规格化描述，不另起视觉风格。

---

## Goals

- 明确 11 个功能模块（主页、注册、登录、工作台、写笔记、笔记列表、笔记详情、分享、评论、收藏、个人主页、关于、AI 润色）的**行为、边界与验收标准**，达到"不写代码也能判断对错"的程度。
- 固化**界面设计契约**：导航结构、页面布局、视觉令牌、组件清单、交互状态、响应式规则、无障碍要求，使实现结果与参考截图一致。
- 固化三条**强制规范**：统一错误响应格式、依赖管理与镜像、UTF-8 编码。
- 让 AI 润色功能具备可演示性：即使不配置大模型密钥，功能流程也完整可跑。

## Non-Goals

- 不做公开的文章广场 / 发现页 / 他人主页浏览；笔记默认私密，对外可见性完全由分享开关控制。
- 不做邮箱验证、忘记密码、第三方登录、短信验证等账号增强能力。
- 不做笔记回收站、协同编辑、实时协作、导入导出（Markdown/PDF）。
- 不做草稿自动保存与冲突合并；保存为显式操作。
- 不做移动端专属交互（底部操作条、全屏弹窗重设计）。
- 不做后台管理端、数据统计看板、附件多文件批量管理。
- 本轮不产出完整数据库表结构、API 出入参清单与完整错误码表（见 Deferred Questions）。

## Recommended Approach

采用**前后端分离的轻量形态**：Flask 提供页面路由与 `/api/*` 两套路由，页面只输出 HTML 骨架，数据一律由前端 `fetch` 以 JSON 获取。理由是项目提示词中"后端统一返回 `{code, message}`、前端只显示 `message`"的规范天然适配 JSON API，且 AI 润色弹窗、划词替换、收藏切换、评论发布等交互都依赖局部刷新。

配套四项关键选型（已与 master 确认）：

| 决策点 | 选择 | 理由 |
|---|---|---|
| 编辑器 | 原生 `<textarea>` + 自定义右键菜单 | 与截图工具栏完全一致；`selectionStart/End` 可精确取词与回写，零依赖 |
| Markdown 渲染 | 前端渲染（本地 vendor 的 marked.js + DOMPurify） | 详情页与写作预览共用一套逻辑，预览无延迟 |
| AI 调用 | 同步请求 + 前端加载态 | 与截图弹窗形态一致；超时与错误分支简单可控 |
| 数据访问 | Flask-SQLAlchemy + Flask-Login | 5 张表 + 版本快照 + 标签筛选，ORM 维护成本明显更低 |

## Alternatives Considered

| 方案 | 优点 | 缺点 | 决策 |
|---|---|---|---|
| REST JSON API + 原生 JS | 契合统一错误响应规范；交互局部刷新；页面与数据职责清晰 | 需要额外写前端请求封装 | **采纳** |
| Flask Jinja 服务端渲染 | 依赖少、首屏直出 | AI 弹窗、划词替换、收藏等交互别扭；出错提示需刷新页面 | 否决 |
| 混合（页面模板 + 局部 API） | 折中 | 两套心智模型，错误提示路径不统一 | 否决 |
| contenteditable 富文本编辑器 | 划词右键天然契合 | 编辑内容是 HTML，与 Markdown 原文存储冲突，脏 HTML 清洗成本高 | 否决 |
| 引入第三方 Markdown 编辑器（EasyMDE 等） | 工具栏与快捷键开箱即用 | 引入依赖、右键菜单与视觉需大改造 | 否决 |
| 后端渲染 Markdown | 前端零渲染依赖 | 预览需往返请求；前后端两套渲染易不一致 | 否决 |
| SSE 流式返回润色结果 | 逐字呈现体验好 | Flask 需流式响应，前端要处理分片与中断，复杂度显著上升 | 否决（列为后续可选增强） |
| 标准库 sqlite3 + 手写 SQL | 除 Flask 外零依赖 | 6 张表的查询、事务、登录态都要自建 | 否决 |

## Architecture

```
┌─────────────────────────────────────────────────────────┐
│ 浏览器（原生 HTML + CSS + JS，多页面）                     │
│  templates/*.html    static/css/base.css + 页面样式        │
│  static/js/api.js（统一 fetch + code/message 拦截）        │
│  static/js/vendor/marked.min.js, purify.min.js            │
└───────────────────────┬─────────────────────────────────┘
                        │  fetch → {"code","message","data"}
┌───────────────────────▼─────────────────────────────────┐
│ Flask 应用                                               │
│  ├─ 页面路由：/ /login /register /about /workspace        │
│  │            /notes /notes/new /notes/<id>              │
│  │            /notes/<id>/edit /profile /s/<token>       │
│  ├─ API 路由：/api/auth/*  /api/notes*  /api/comments/*   │
│  │            /api/favorites  /api/upload  /api/ai/polish │
│  └─ services/：auth · note · comment · share · favorite    │
│                 ai · upload（业务逻辑集中于此）             │
└───────────────────────┬─────────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────────┐
│ SQLite（Flask-SQLAlchemy 管理）                          │
│  users · notes · note_versions · comments · favorites     │
└─────────────────────────────────────────────────────────┘
                        │
                 大模型 API（OpenAI 兼容 /chat/completions，可回退本地模拟）
```

**模块职责与边界**

- 页面路由只负责渲染 HTML 骨架与会话态注入，不做业务判断；所有数据由前端调用 API 获取。
- `services/` 承载全部业务规则（权限判定、状态流转、版本快照、AI 调用与回退）。路由层只做参数提取与响应封装。
- `api.js` 是前端唯一出口：统一注入 `credentials`、解析 `{code, message, data}`、`code != "OK"` 时弹 `message`、遇到 `UNAUTHORIZED` 统一跳登录页。页面脚本不得直接写 `fetch`。

**核心数据实体（概念级）**

| 实体 | 关键属性 | 关系 |
|---|---|---|
| 用户 | 邮箱（唯一）、用户名、密码哈希、注册时间 | 1:N 笔记、评论、收藏 |
| 笔记 | 标题、正文（Markdown 原文）、标签、状态（草稿/已发布）、分享开关、分享令牌、分享密码哈希、评论开关、创建/更新时间 | N:1 用户；1:N 版本快照、评论；N:N 收藏 |
| 版本快照 | 标题、正文、标签、快照时间 | N:1 笔记 |
| 评论 | 内容、展示名（登录用户名或访客昵称）、时间 | N:1 笔记 |
| 收藏 | 收藏时间 | 用户 × 笔记 唯一 |

完整字段类型、索引与约束在技术方案阶段细化。

## Interface Design Contract

### Experience and Journeys

**体验目标**：像翻开一本纸质手账那样踏实、安静；界面退到内容之后，让人愿意坐下来写。

**四种角色的主要旅程**

1. **新访客**：主页 → 点"开始记录" → 注册（自动登录）→ 工作台 → 新建文章 → 写作（可划词润色）→ 发布 → 详情页 → 打开分享并复制链接。
2. **回访用户**：登录 → 工作台看统计与最近文章 → 我的文章（搜索 / 标签 / 状态筛选）→ 进入编辑 → 存草稿。
3. **分享访客**：打开 `/s/<token>` →（若设密码）输入密码 → 阅读渲染后的正文 →（若评论开启）填昵称评论。
4. **AI 润色旅程**：编辑区划词 → 右键 → "AI 润色" → 弹窗加载 → 对照左右文本 → "确认替换" 或 "取消"。

**信息层级与导航模型**

- 未登录顶部导航：`登录` / `注册` / `关于`；已登录顶部导航：`我的文章` / `个人主页` / `关于` / `退出`。
- 登录后所有页面共用同一顶栏 + 同一羊皮纸底；内容区为单列卡片流，页宽约 960–1100px 居中。
- 详情页自上而下：标题与操作 → 元信息 → 正文 → 分享设置 → 评论；两层操作与内容边界靠卡片分隔，不做标签页切换。
- 渐进披露：分享设置与评论区使用可折叠卡片，默认展开、可收起。
- 失败恢复路径：AI 弹窗失败 → 保留原文并提示，可直接重试；分享密码错误 → 停留密码页并提示，不清空输入框。

### Visual System

**视觉方向**：纸质手账风。未登录页面以浅色木桌静物照（`图片素材/个人笔记主页.jpg`）满屏铺底，左侧留白承载文案；登录后统一使用羊皮纸底纹（`图片素材/个人笔记-笔记背景.jpg`），四角带手绘花角、左下羽毛笔与右上罗盘水印。

**签名元素**：**羊皮纸质感 + 手绘花角/羽毛笔水印**，跨所有登录后页面保持一致；这是唯一"花力气"的视觉点，其余元素保持克制（白卡片、细描边、弱阴影）。

**字体与排版**

- 标题（页面标题、卡片标题、笔记标题、统计数字）：衬线字体栈 `"Noto Serif SC", "Source Han Serif SC", "SimSun", serif`。
- 正文与控件：无衬线字体栈 `system-ui, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 字号阶梯：页面标题 26–30px / 笔记标题 28–30px / 卡片标题 17px / 正文 15px / 元信息 13px / 提示 12px。主页 Hero 主标题为独立档 56–64px，字距加宽。
- 行高：正文 1.8–1.9（长文阅读舒适）。

**形状、描边、阴影、动效**

- 圆角 6px（按钮、输入框）、8px（卡片）、999px（状态标签与开关）。
- 描边 1px `--border`；卡片阴影 `0 2px 8px rgba(107,78,46,.08)`。
- 按钮：主按钮实底 `--brown` + 白字；次按钮白底 + 1px 描边 + 深色字；文字按钮无底色。
- 图标：统一线性图标（描边风），与截图一致；装饰性矢量直接内联 SVG，不使用图标字体。
- 动效克制：仅按钮/开关 hover 200ms、弹窗淡入 160ms、加载态旋转；`prefers-reduced-motion` 下全部取消过渡。

| 登录失败 | 邮箱或密码错误 |
| 必填校验 | 请填写邮箱 / 请填写密码 / 两次输入的密码不一致 |
| 邮箱重复 | 该邮箱已被注册 |
| 用户名重复 | 该用户名已被使用 |
| AI 加载中 | 润色中… |
| AI 未配置 | 尚未配置大模型，当前展示模拟润色结果 |
| AI 超时 | 润色请求超时，请稍后重试 |
| AI 失败 | 润色失败，请稍后重试 |
| AI 结果为空 | 未能生成润色结果，请调整选中内容后重试 |
| 上传过大 | 图片大小不能超过 5MB |
| 上传类型 | 仅支持 png、jpg、jpeg、webp、gif 格式的图片 |

## 功能需求明细

### F1 用户注册

- 表单字段：邮箱、用户名、密码、确认密码。
- 校验规则：邮箱格式合法且全局唯一；用户名 2–20 个字符且唯一；密码 ≥ 6 位；两次密码必须一致。校验在提交时前后端同时进行，前端即时提示、后端作为最终防线。
- 成功行为：自动登录并跳转工作台。
- 失败行为：停留在注册页，字段下方显示对应中文提示，已填内容不丢失。
- 已登录用户访问注册页 → 直接跳转工作台。

### F2 用户登录

- 表单字段：邮箱、密码。
- 成功行为：写入会话并跳转工作台；已登录访问登录页 → 直接跳转工作台。
- 失败行为：统一提示"邮箱或密码错误"，不区分"账号不存在"与"密码错误"。
- 保持范围：会话级登录（关闭浏览器即失效），不做"记住我"与固定有效期。
- 退出登录：清空会话并回到主页。

### F3 主页

- 未登录：品牌 Hero（背景使用 `图片素材/个人笔记主页.jpg`）、主标题"记录生活 · 书写成长 / 遇见美好"、简介段落、主按钮"开始记录"（跳注册）、次按钮"了解更多"（跳关于）、四项特性图标区（简洁易用 / 云端同步 / 隐私保护 / 灵活分类，各带一句说明）。
- 已登录：顶栏切换为登录态菜单，Hero 主按钮改为进入工作台。
- 四项特性文案中的"云端同步"按当前实现口径表述为本地存储的可靠性说明，不得出现与实现不符的承诺（详见 Deferred Questions）。

### F4 工作台

- 三张统计卡：草稿数量、已发布数量、收藏数量；数字实时反映当前用户数据。
- 最近文章：按更新时间倒序展示最近 5 篇，每行含笔记标题、状态标签、更新时间；点击进入详情。
- 操作按钮：`新建文章` → 写笔记页；`我的文章` → 列表页。
- 无笔记时最近文章区显示空状态文案。

### F5 笔记管理

- 新建笔记：标题（必填，≤ 100 字）、标签（选填，逗号分隔，最多 5 个，每个 ≤ 12 字）、正文（Markdown 原文）。
- 工具栏按钮：H1、H2、加粗、斜体、引用、行内代码、无序列表、有序列表、插入链接、插入图片；点击后在光标处插入对应 Markdown 语法，若有选中文本则包裹选中内容。
- 预览：点击"预览"在编辑区原位切换为渲染后的 Markdown，再次点击返回编辑。
- 保存草稿：状态置为草稿，停留在编辑页并提示"草稿已保存"。
- 发布文章：状态置为已发布并记录发布时间，跳转至详情页。
- 编辑已发布笔记后再保存：保持已发布状态，更新更新时间，并生成一条版本快照。
- 删除笔记：详情页操作，二次确认后连同评论、收藏、版本快照一并删除。
- 详情页元信息：状态标签、标签 chip、创建时间、更新时间。
- 版本记录规则：每次"保存（更新已有笔记）"与"发布"前，把当前标题、正文、标签快照写入版本记录；新建笔记不产生版本记录。

### F6 我的文章（列表页）

- 展示当前用户的全部笔记，按更新时间倒序。
- 关键词搜索：匹配标题与正文，即时过滤。
- 标签筛选：从用户已有标签中多选过滤。
- 状态筛选：全部 / 草稿 / 已发布。
- 筛选条件可叠加，页面显示当前筛选条件数量并支持一键清空。
- 无结果时显示空状态文案，与"还没有任何笔记"区分。
- 笔记量在数十篇量级内，一次加载全部，不做分页。

### F7 分享

- 分享开关：开启时生成唯一分享令牌与分享链接；关闭后链接立即失效。
- 密码：可选。设置后访客需输入密码；输入留空并保存表示移除密码。
- 链接操作：展示完整链接并提供"复制"按钮，复制成功提示"已复制链接"。
- 分享页 `/s/<token>`：
  - 分享关闭 → 显示"分享已关闭"，不泄露笔记标题与正文。
  - 设置了密码且未通过验证 → 只显示密码输入界面，不返回正文内容。
  - 密码错误 → 提示"密码错误，请重新输入"，可重试。
  - 验证通过 → 渲染标题、正文、更新时间；是否显示评论区由评论开关决定。
- 访客无需登录即可阅读。

### F8 评论

- 评论开关：笔记作者可开关评论区；开关关闭时访客与作者都不能提交新评论，历史评论默认折叠隐藏。
- 登录用户评论：展示用户名与时间。
- 分享访客评论：提交前需填写昵称（1–20 字符），提交后展示该昵称，并在界面标注为访客来源。
- 删除权限：笔记作者可删除该笔记下任意评论；登录用户可删除自己的评论；访客不可删除任何评论。
- 详情页标题处显示评论数量。

### F9 收藏

- 详情页提供收藏 / 取消收藏切换，状态即时反馈并给出 Toast 提示。
- 允许收藏自己的笔记，不做限制。
- 个人主页展示收藏列表，按收藏时间倒序；取消收藏后从列表移除。

### F10 个人主页

- 个人信息展示：用户名、邮箱、注册时间（只读）。
- 我的收藏：收藏笔记列表，点击进入详情。
- 笔记历史：选择某篇笔记后展示其版本列表（时间倒序），可查看任一旧版本的标题、正文、标签（只读）；旧版本不支持一键恢复。
- 无收藏 / 无版本记录时显示对应空状态。

### F11 AI 润色

- 入口：写笔记 / 编辑笔记页的编辑区。
- 触发：鼠标划词选中文本 → 右键 → 上下文菜单出现"AI 润色"→ 点击后弹出润色弹窗。无选中文本时菜单项置灰不可点击；未选中任何内容时右键不出现该菜单项。
- 弹窗结构：标题"AI 文本润色"；左侧"原文"区（只读，展示选中文本）；右侧"润色结果"区（可选择复制）；右下角"取消"与"确认替换"。
- 取消：关闭弹窗，原文一字不改。
- 确认替换：用润色结果替换编辑区中**原先选中的那一段**，其余内容不变；替换后光标定位到替换内容末尾；弹出成功提示。
- 处理中：调用期间展示加载态（"润色中…"），按钮禁用防重复提交。
- 失败：显示对应中文错误提示，保留原文，提供"重试"；取消后不改变任何内容。
- 润色指令要求：要求模型仅返回润色后的文本，不得附加解释、前后缀或引号；保持原文语言、Markdown 标记与段落结构不变；提升流畅度、清晰度与表达质量，不改变原意、不添加原文没有的事实。
- 输入长度上限：单次选中文本 ≤ 5000 字，超出时提示"选中内容过长，请分段润色"。
- 模型接入：后端通过配置项指定接口地址、密钥、模型与超时，走 OpenAI 兼容的对话补全接口。
- **降级要求**：未配置密钥或调用不可用时，自动回退为本地模拟润色，结果区明确标注"模拟结果"，保证功能流程完整可演示。
- 范围限定：仅编辑页（textarea）支持选词润色；详情页渲染后的正文不提供该入口。

### F12 关于页面

- 内容：项目简介、功能概览、技术栈说明、使用提示（如何分享、如何开启评论、如何使用 AI 润色）。
- 不包含联系方式表单、不收集用户输入。

### R1 全局规范：错误处理

- 所有接口统一返回 `{ "code": "...", "message": "中文提示", "data": ... }`；成功时 `code` 为 `OK`。
- 前端只展示后端返回的 `message`，不得在前端拼接或硬编码业务错误文案。
- 后端不得把异常堆栈、SQL 语句、密钥等内部信息写入 `message`；未知异常统一返回"服务器繁忙，请稍后重试"。
- 初始 code 词表（最小集，实现阶段可扩充并保持语义稳定）：`OK`、`PARAM_ERROR`、`UNAUTHORIZED`、`FORBIDDEN`、`NOT_FOUND`、`CONFLICT`、`SHARE_CLOSED`、`SHARE_PASSWORD_REQUIRED`、`SHARE_PASSWORD_WRONG`、`AI_NOT_CONFIGURED`、`AI_TIMEOUT`、`AI_ERROR`、`UPLOAD_TOO_LARGE`、`UPLOAD_TYPE_ERROR`、`SERVER_ERROR`。

### R2 全局规范：依赖管理

- `requirements.txt` 锁定精确版本号（使用 `==`），不使用范围符号。
- 安装使用国内镜像源（如清华 TUNA），并把镜像配置写进项目的安装说明。
- 前端第三方库（marked.js、DOMPurify）下载到 `static/js/vendor/` 本地引入，不依赖外部 CDN。

### R3 全局规范：字符编码

- 全链路 UTF-8：文件读写、数据库连接、HTTP 响应头统一声明 `charset=utf-8`，禁止使用 GBK。

## Data Flow

**AI 润色时序**

1. 用户在编辑区划词 → 记录 `selectionStart/End` 与选中文本。
2. 右键 → 菜单点击"AI 润色" → 打开弹窗，左侧填入选中文本，右侧进入加载态。
3. 前端调用润色接口（携带选中文本）→ 后端构造提示词 → 调用模型（超时 20 秒）。
4. 成功：返回润色文本 → 右侧展示，附"复制"能力。
   失败：返回错误 code → 右侧显示中文提示与"重试"按钮。
5. 用户点"确认替换" → 用保存的选区位置将结果回写编辑区 → 关闭弹窗并提示。
   用户点"取消" / Esc / 点遮罩 → 关闭弹窗，编辑区不变。

**分享访问时序**

1. 访客打开 `/s/<token>` → 服务端校验令牌与分享开关。
2. 分享关闭 → 返回分享关闭页面（不含笔记内容）。
3. 已设密码且会话未通过验证 → 返回密码输入页面（不含笔记内容）。
4. 校验通过 → 返回正文页面；评论开关开启时，评论区可提交昵称 + 内容。

**笔记保存时序**

1. 提交标题、标签、正文与目标状态（草稿 / 已发布）。
2. 若为更新已有笔记：先把更新前的标题、正文、标签写入版本快照，再更新主体。
3. 更新更新时间；发布时写入发布时间。
4. 返回最新笔记数据，前端按目标状态跳转或留在当前页。

## Error Handling

| 场景 | 处理 |
|---|---|
| 表单校验失败 | 前端即时提示 + 后端 `PARAM_ERROR` 兜底，字段级中文文案 |
| 未登录访问写操作 | `UNAUTHORIZED`，前端提示并跳转登录页 |
| 操作他人笔记 / 评论 | `FORBIDDEN`，提示"没有权限执行该操作" |
| 资源不存在或已删除 | `NOT_FOUND`，提示"内容不存在或已被删除" |
| 分享已关闭 | `SHARE_CLOSED`，页面显示"分享已关闭" |
| 分享需密码 | `SHARE_PASSWORD_REQUIRED`，进入密码输入态 |
| 分享密码错误 | `SHARE_PASSWORD_WRONG`，保留输入框内容并提示重试 |
| 大模型未配置 | `AI_NOT_CONFIGURED`，回退模拟结果并标注 |
| 大模型超时（>20s） | `AI_TIMEOUT`，提示"润色请求超时，请稍后重试"+ 重试按钮 |
| 大模型返回异常/空结果 | `AI_ERROR` 或空结果提示，保留原文 |
| 图片超限或类型不符 | 前端先拦一次，后端再校验并返回对应中文提示 |
| 上传写盘失败 | `SERVER_ERROR`，提示"图片上传失败，请稍后重试" |
| 未捕获异常 | 统一 `SERVER_ERROR` + "服务器繁忙，请稍后重试"，同时服务端记日志 |

所有失败路径的共同要求：**不破坏用户已输入的内容**，并给出明确的下一步动作。

## Security

- **口令存储**：用户密码与分享密码均只存哈希（Werkzeug 生成），永不落库明文、永不回传前端。
- **会话**：使用 Flask 签名会话 Cookie，设置 `HttpOnly` 与 `SameSite=Lax`；写操作一律校验登录态。密钥通过配置项/环境变量注入，不进代码仓库。
- **越权防护**：所有涉及笔记、评论、版本、收藏的接口必须先校验资源归属，禁止仅凭前端传入的 id 直接操作。
- **分享令牌**：使用不可预测的随机串，不使用自增 id；关闭分享后令牌立即失效。
- **XSS**：Markdown 渲染结果一律经 DOMPurify 消毒；后端存储原文不做渲染，避免服务端模板注入。用户输入在非 Markdown 场景（标题、标签、评论）按纯文本处理。
- **上传**：白名单校验扩展名与 MIME，限制 5MB，重命名文件（不信任原始文件名），存放于静态目录且禁止执行权限。
- **密钥与错误信息**：大模型密钥仅存服务端配置；`message` 不得包含堆栈、SQL、密钥等内部信息。
- **滥用控制**：润色接口限制单次输入长度（≤ 5000 字）并做基础频率限制，避免被当作通用文本接口滥用。
- **数据隔离**：草稿与未分享笔记对所有其他用户（含持有他人链接者）不可见。

## Boundaries and Dependencies

| 单元 | 拥有 | 不拥有 | 依赖 |
|---|---|---|---|
| 页面路由 | HTML 骨架、会话态注入 | 业务规则 | 模板、服务层 |
| `/api/*` 路由 | 参数提取、响应封装 | 业务规则 | 服务层 |
| 服务层 | 全部业务规则与权限判定 | 会话读写细节、SQL 生成 | 模型层、AI 配置 |
| 模型层 | 表定义、关系、约束 | 业务判断 | SQLite、SQLAlchemy |
| 前端页面脚本 | 渲染与交互 | 直接请求、错误文案 | `api.js`、渲染器 |
| `api.js` | 请求封装、code 拦截、跳登录 | 业务语义 | 无 |
| AI 服务 | 提示词、调用、超时、回退 | 编辑器选区处理 | 外部模型接口（可缺省） |
| 外部依赖 | — | — | Flask / Flask-SQLAlchemy / Flask-Login / requests / marked.js / DOMPurify |

**外部依赖引入的假设**

- 大模型服务需 OpenAI 兼容的对话补全接口；若接口不兼容，只需替换 AI 服务内部实现，其余模块不受影响。
- 大模型输出质量与响应时间不可控，因此必须有超时与回退路径，且失败不能影响笔记内容。
- 前端库（marked.js、DOMPurify）本地引入，版本在实现时锁定并记录来源。

## Testing

项目无既有测试框架，采用**手动验收为主 + 关键逻辑单元测试为辅**：

- **验收清单**：按 F1–F12 与"视觉验证清单"逐项走查，每项给出明确通过条件（例如 F7 分享：关闭分享后打开链接必须不含标题与正文，接口返回 `SHARE_CLOSED`）。
- **AI 润色双路径**：分别在"配置密钥"与"未配置密钥"两种状态下各走一遍完整流程，验证回退标注、超时提示与重试。
- **权限矩阵验证**：准备两个账号 + 一个未登录访客，交叉验证笔记、评论、版本、收藏、分享的越权行为全部被拒。
- **边界用例**：空标题、超长标题、超 5 个标签、密码不一致、重复邮箱、空正文发布、超长润色选区、非图片文件上传、分享密码留空移除、连续快速点击"确认替换"。
- **单元/集成测试（轻量）**：注册登录校验、密码哈希、版本快照生成、分享令牌校验、搜索筛选的查询逻辑、AI 服务的提示词构造与回退分支。
- **编码验证**：含中文、emoji、Markdown 特殊字符的笔记在保存、渲染、分享全链路上不发生乱码。

## Rollout

- 本地运行的独立应用，无线上迁移与灰度需求，不需要特性开关或回滚方案。
- 首次运行步骤：创建虚拟环境 → 按国内镜像安装锁定依赖 → 初始化数据库 → 启动服务 → 浏览器访问。
- 首次启动自动建表并创建静态上传目录；无种子数据。

## Deferred Questions

以下为非阻塞项，实现阶段按默认假设处理即可，确认后可在实现中直接调整：

1. **完整技术方案**：数据库字段类型与索引、API 出入参清单、完整错误码表、配置项命名 —— 默认另行产出技术方案文档，本文档不展开。
2. **"云端同步"表述**：主页四项特性中的该文案保留截图原文，待实现确认存储口径后统一措辞。
3. **个人信息是否可编辑**：默认只读展示用户名、邮箱、注册时间；若需支持改用户名/改密码，作为独立迭代。
4. **关于页面正文**：默认按"项目简介 + 功能概览 + 技术栈 + 使用提示"撰写，定稿文案可替换。
5. **AI 模型与提示词默认值**：默认使用 OpenAI 兼容接口的最低成本模型，提示词按 F11 指令要求实现，允许上线前微调。
6. **模拟润色实现方式**：默认采用轻量规则改写（语序与用词微调），确保可复现、无外网依赖；不追求与真实模型输出相似。
7. **笔记标题是否允许重复**：默认允许，列表以标签区分。
8. **标签管理**：默认从用户已有笔记聚合生成，不提供独立标签管理页，不支持重命名与删除标签。
